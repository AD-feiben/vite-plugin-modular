# Vite Plugin Modular 实现步骤文档

## 1. 插件核心功能实现

### 1.1 解析mode参数
- 调整插件代码，从Vite配置的`mode`中提取模块名和环境名
- 模式格式：`[moduleName]-[envName]`，如 `module1-dev`
- 支持从环境变量中读取模式

### 1.2 加载配置文件
- 自动生成和加载项目根目录下的 `modular.config.[js/json]`
- 解析当前模式对应的模块配置
- 验证模块和环境是否存在

### 1.3 实现源码路径唯一性校验
- 在插件初始化阶段，校验所有模块的 `sourceDir` 是否唯一
- 如果发现重复的 `sourceDir`，抛出错误，提示用户修改配置

### 1.4 实现路径拼接函数
- 实现 `getFullSourceDir` 函数，自动拼接完整的源码路径：`src/modules/${module.sourceDir}`
- 实现 `getFullEntryPath` 函数，自动拼接完整的入口路径：`src/modules/${module.sourceDir}/${module.entry}`

### 1.5 实现HTML标题和入口JS替换
- 使用Vite的`transformIndexHtml`钩子
- 替换HTML页面标题为配置的 `title`
- 替换入口JS脚本为完整的入口路径

### 1.6 配置构建输出目录
- 动态配置 `build.outDir` 为 `dist/[module.outputDir]`
- 支持用户自定义输出目录

### 1.7 实现环境变量配置
- 配置 `envDir` 为固定值 `env`
- 配置 `envPrefix` 为 `VITE_`
- 注入环境变量 `VITE_MODULE_NAME`
- 实现 `toSnakeCase` 转换函数
- 将 `moduleConfig.define` 中的环境变量 key 转换为 SNAKE_CASE 格式，然后以 `import.meta.env.VITE_[SNAKE_CASE_KEY]` 格式注入

## 2. 配置文件管理

### 2.1 实现主配置文件的自动生成
- 每个模块包含 `sourceDir` 配置，只记录子路径
- 确保默认环境dev和prod自动添加到配置中
- 支持使用 `define` 对象配置所有环境共享的环境变量
- 移除 `envDir` 配置项，所有模块共用 `env` 目录

## 3. 环境变量文件管理

### 3.1 实现环境变量文件的自动生成
- 所有文件存放在 `env` 目录下
- 命名规则：`.env.[模块名]-[环境名]`
- 确保每个模块的每个环境都有对应的 env 文件

### 3.2 实现 env 文件的自动清理
- 删除模块时，自动清理所有相关的 env 文件
- 删除环境时，自动清理对应的 env 文件

## 4. CLI工具开发

### 4.1 实现CLI入口和命令解析
- 使用 `commander` 库实现命令解析
- 支持以下命令：`add`、`delete`、`addEnv`、`deleteEnv`、`list`、`config`、`ui`

### 4.2 实现add命令
- 交互式模块创建，带重复校验
- 加载 CLI 配置文件，获取模板目录和JSON缩进配置
- 询问模块名称，带重复校验
- 询问模块标题
- 询问源码路径，默认 `[模块名]`，带唯一性校验
- 询问入口文件，默认 `main.ts`
- 询问输出目录，默认模块名
- 自动添加dev和prod默认环境
- 循环询问额外环境名，展示已确认的环境列表
- 生成所有环境的 env 文件
- 自动添加相关命令
- 根据拼接后的完整源码路径创建模块目录
- 若 CLI 配置中指定了模板目录且模板目录存在，则拷贝模板文件到新模块目录中
- 使用CLI配置中的jsonIndent保存配置

### 4.3 实现delete命令
- 支持直接指定模块名
- 支持列表选择
- 自动清理相关命令、目录和所有 env 文件
- 根据拼接后的完整源码路径删除模块目录
- 使用CLI配置中的jsonIndent保存配置

### 4.4 实现addEnv命令
- 模块选择
- 循环输入新环境名，展示当前环境列表
- 严格的环境名校验
- 生成对应的 env 文件
- 自动添加相关命令
- 使用CLI配置中的jsonIndent保存配置

### 4.5 实现deleteEnv命令
- 模块选择
- 显示当前环境列表，标记默认环境
- 禁用默认环境的选择
- 删除对应的 env 文件
- 自动清理相关命令
- 使用CLI配置中的jsonIndent保存配置

### 4.6 实现list命令
- 表格展示模块信息
- 包含源码路径（只显示子路径）、完整源码路径、入口文件、输出目录、环境列表等
- 标记默认环境

### 4.7 实现config命令
- 交互式配置修改
- 支持修改模块标题、源码路径、入口文件、输出目录
- 修改源码路径时进行唯一性校验
- 支持环境管理，默认环境不可删除
- 支持添加/删除共享环境变量
- 使用CLI配置中的jsonIndent保存配置

### 4.8 实现ui命令
- 启动Web服务器
- 提供可视化管理界面
- 支持模块管理
- 支持环境管理
- 支持配置修改
- 支持实时预览

### 4.9 实现CLI配置文件加载
- 支持加载 `vmod.config.json` 和 `vmod.config.js`
- 实现 `getProjectIndent` 函数，自动获取项目代码缩进量
- 如果配置中没有指定 `jsonIndent`，则使用自动获取的缩进量

### 4.10 实现模块模板拷贝
- 实现 `copyTemplateFiles` 函数，递归拷贝模板文件到模块目录
- 支持多级目录结构的模板

## 6. 注意事项

### 6.1 默认环境处理
- 确保默认环境dev和prod在所有模块中都存在
- 所有环境相关操作都要检查并排除默认环境
- CLI交互中要清晰标记默认环境
- 默认环境不可删除，避免误操作

### 6.2 环境变量注入
- 正确处理不同数据类型，确保所有环境变量都以 `VITE_` 前缀注入
- 支持多种入口文件类型（.ts, .js, .jsx, .tsx等）

### 6.3 跨平台兼容性
- 确保所有文件路径操作都使用 `path.join` 或 `path.resolve`
- 避免使用平台特定的文件分隔符

### 6.4 错误处理
- 提供清晰的错误提示和帮助信息
- 捕获并处理所有可能的异常
- 确保用户能够理解并解决遇到的问题

### 6.5 命令缩写和别名
- 支持命令缩写，提高用户体验
- 提供清晰的命令说明和帮助信息

### 6.6 可视化UI界面
- 确保UI界面与CLI功能保持一致
- 提供实时预览和反馈
- 支持所有CLI命令的功能

### 6.7 配置文件备份
- 定期备份配置文件，避免误操作导致数据丢失
- 提供配置恢复功能

### 6.8 模块模板机制
- 支持用户自定义模块模板
- 提供默认模板
- 支持模板版本管理

### 6.9 插件与Vite版本兼容性
- 确保插件与Vite 5.x版本兼容
- 定期更新插件以支持最新的Vite版本

### 6.10 TypeScript类型定义
- 提供完整的TypeScript类型定义
- 确保类型定义与实际实现保持一致
