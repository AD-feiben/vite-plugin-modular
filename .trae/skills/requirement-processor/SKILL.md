# 需求处理器

此技能帮助您系统地处理用户需求，确保在修改代码之前清晰理解并妥善记录需求。

## 工作原理

1. **识别内容**：分析用户输入，判断是否为需求
2. **确认细节**：必要时询问澄清问题，确保完全理解需求
3. **记录需求**：将确认的需求记录到结构化文档中
4. **实现变更**：根据文档中的需求修改代码
5. **验证实现**：测试变更确保满足需求

## 何时调用

当以下情况发生时调用此技能：
- 用户提供新功能请求
- 用户报告bug
- 用户要求改进现有功能
- 用户描述任何代码库变更
- 用户提及需求、功能或bug

## 使用示例

### 示例1：新功能请求

**用户输入：**
"我想添加一个新命令来列出所有模块及其状态。"

**处理流程：**
1. 确认功能细节
2. 将需求记录到文档中
3. 实现新命令
4. 测试命令确保正常工作

### 示例2：Bug修复

**用户输入：**
"删除命令没有正确删除模块目录。"

**处理流程：**
1. 确认bug细节
2. 将bug记录到文档中
3. 修复删除命令
4. 测试修复确保正常工作

## 需求文档格式

需求应记录为结构化格式，包括：

- **需求ID**：唯一标识符
- **标题**：需求的简要描述
- **描述**：详细说明需要做什么
- **优先级**：高、中、低
- **状态**：待办、进行中、已完成
- **实现说明**：关于如何实现需求的具体细节

## 实现步骤

1. **分析**：理解用户请求并识别所有需求
2. **确认**：与用户验证细节，确保理解正确
3. **文档**：创建或更新需求文档
4. **规划**：确定必要的代码变更
5. **实现**：进行代码变更
6. **测试**：验证变更是否符合预期
7. **交付**：向用户展示变更

## 最佳实践

- 在进行变更前始终与用户确认需求
- 清晰、全面地记录所有需求
- 彻底测试变更，确保满足需求
- 在整个过程中保持与用户的沟通
- 保持一致的需求处理方法
